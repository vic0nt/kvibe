# Формат файла данных

Живая спецификация раздела 6 REQUIREMENTS.md — при любом изменении формата (новая
`formatVersion`) этот документ ОБЯЗАН обновляться в том же коммите, что и код. Обоснование
конкретных решений (почему CRC32C, почему big-endian, почему бит tombstone, а не сигнальная
длина) — в [ADR-0002](adr/0002-record-format-crc32c-byte-order.md), здесь не повторяется.

Реализация: `kvibe.format.FileHeader` и `kvibe.format.RecordCodec`.

## Порядок байтов

Big-endian — значение `ByteBuffer` по умолчанию.

## Заголовок файла (16 байт, пишется один раз при создании)

| Смещение | Поле | Тип | Значение |
|---|---|---|---|
| 0 | magic | 4 байта ASCII | `KVB1` |
| 4 | formatVersion | uint16 | `1` (текущая версия) |
| 6 | flags | uint16 | зарезервировано, `0` |
| 8 | reserved | 8 байт | нули |

Магия или версия новее `CURRENT_FORMAT_VERSION` → `UnsupportedFormatException` при `open()`
(FR-9). Открытие не пытается угадать содержимое незнакомого файла.

## Запись

| Поле | Тип | Комментарий |
|---|---|---|
| crc32c | uint32 | по всем полям записи после себя |
| timestampMillis | int64 | момент записи; понадобится для сжатия (v0.2) |
| flags | uint8 | бит 0 — tombstone, остальные биты не используются |
| keyLength | uint16 | 1…65535 |
| valueLength | uint32 | 0…16 МиБ (`RecordCodec.MAX_VALUE_LENGTH`) |
| key | keyLength байт | |
| value | valueLength байт | у tombstone-записи длина всегда 0 |

Tombstone — отдельный бит, а не сигнальное значение `valueLength` (например, `-1`): так
`valueLength` остаётся всегда корректной неотрицательной длиной, а пустое значение
(`new byte[0]`) остаётся отличимым от удаления ключа (FR-2).

`RecordCodec.decode` проверяет `keyLength`/`valueLength` на допустимый диапазон **до** аллокации
массивов под key/value — испорченное поле длины не должно приводить к
`NegativeArraySizeException` или попытке выделить гигабайты под мусор (TR-4).

## Правило восстановления

Файл читается последовательно от конца заголовка. Запись принимается, если она целиком
помещается в оставшиеся байты файла и её CRC32C совпал. Первая непринятая запись (не
поместилась целиком — торн-запись, либо не совпал CRC — порча) останавливает скан и задаёт
точку усечения: `channel.truncate(offsetOfFailedRecord)`. Кодек не различает торн-запись и
порчу — оба случая обрабатываются одинаково остановкой и усечением (`kvibe.recovery.Recovery`).

Факт усечения и число отброшенных байт логируются на уровне `INFO` (`KvibeStore.open`).

## Позиция значения без повторного разбора записи

`RecordCodec.valueOffsetInRecord(keyLength)` возвращает смещение первого байта значения
относительно начала записи. И путь записи (`KvibeStore.put`), и восстановление
(`kvibe.recovery.Recovery`) используют его, чтобы посчитать абсолютное смещение значения в
файле и сохранить его напрямую в `Loc(offset, length)` — так `get()` не перепарсивает всю
запись на каждое чтение, а сразу читает `length` байт с `offset`.

## Пределы формата

- Ключ: 1…65 535 байт (`uint16`).
- Значение: 0…16 МиБ (`uint32` с явной верхней границей `RecordCodec.MAX_VALUE_LENGTH`).
- Увеличение любого из пределов — несовместимое изменение формата, требует новой
  `formatVersion` и явной миграции, а не тихой правки констант.

## Совместимость

Формат версионируется с версии `1`. Любое несовместимое изменение этого документа требует
новой `formatVersion` в `FileHeader` и явного решения о (не)обратной совместимости со старыми
файлами — не молчаливой правки уже принятого ADR-0002 (правила ведения ADR, раздел 9
REQUIREMENTS.md).
